# Architecture

haskoin is one Cabal package: a library (`src/Haskoin/`), the `haskoin` executable
(`app/Main.hs`), test suites (`test/`) and a few helper executables. The library holds all
consensus, storage, networking and RPC code; `app/Main.hs` parses options, opens the
database, starts the threads and drives block download.

## Process layout

One GHC process with the threaded runtime. At start-up `runNode` (`app/Main.hs`) reads the
config file, opens RocksDB, loads the block index and UTXO cache, reconciles the stored tip
against the applied UTXO set, and then forks:

- the peer manager (outbound dialer, inbound listener, per-peer reader/writer threads),
- the block download and connect loop,
- the JSON-RPC/REST server (Warp),
- the metrics and health HTTP endpoints,
- a periodic chainstate flush and a periodic forced major GC.

Every writer to the chainstate (block connect, reorg, `invalidateblock`, snapshot load,
flush) takes one re-entrant chain lock (`Haskoin.ChainLock`), the counterpart of Core's
`cs_main`.

## Modules

| Area | Module | Contents |
|---|---|---|
| Types | `Types.hs` | Transactions, blocks, headers, hashes; `cereal` wire serialization |
| Crypto | `Crypto.hs`, `TaprootSighash.hs`, `MuHash.hs` | SHA-256d, HASH160, secp256k1 ECDSA/Schnorr (FFI to libsecp256k1), legacy/segwit/taproot sighash, MuHash3072 |
| Script | `Script.hs` | Script parser and interpreter, all verification flags, P2SH, segwit v0, taproot and tapscript |
| Consensus | `Consensus.hs` | Chain parameters for each network, header and block checks, contextual checks, difficulty, BIP-30/34/68/112/113/141/341 rules, connect/disconnect, reorgs, assumevalid, assumeutxo snapshots |
| Faults | `Fatal.hs` | Keeps I/O and database errors from being recorded as "block invalid" |
| Storage | `Storage.hs` | RocksDB schema (key prefixes) holding headers, blocks, undo data and the UTXO set; UTXO cache with dirty/fresh tracking; with pruning on, a block-file store in Core's `blk*.dat`/`rev*.dat` format |
| Indexes | `Index.hs` | BIP-157/158 block filter index, coinstats index and txospender index, each behind its option |
| P2P | `Network.hs` | Message codec, version handshake, BIP-324 v2 transport, addrman with ASMap (`ASMap.hs`), addrv2, compact blocks (BIP-152), eviction, misbehaviour, bans, SOCKS5/Tor/I2P, BIP-330 (Erlay) reconciliation code using minisketch |
| Download | `Sync.hs`, `app/Main.hs` | Headers-first sync and the block download window |
| Mempool | `Mempool.hs`, `Mempool/Persist.hs`, `Policy/Standard.hs`, `TxOrphanage.hs` | Acceptance, standardness, RBF, package relay, ancestor/descendant limits, cluster ordering, `mempool.dat`, orphan pool |
| Fees | `FeeEstimator.hs` | Confirmation-bucket fee estimation, `fee_estimates.json` |
| Mining | `BlockTemplate.hs` | `getblocktemplate`, `submitblock`, regtest `generate*` |
| RPC | `Rpc.hs`, `CoreArity.hs` | HTTP server, auth, dispatch table, REST, ZMQ publisher; `CoreArity.hs` is Core's argument-count table, generated by `tools/gen_core_arity_hs.py` |
| Wallet | `Wallet.hs`, `Wallet/Persist.hs`, `Bip21.hs`, `Payjoin.hs` | BIP-32/39 keys, descriptors, miniscript, PSBT (BIP-174/370), coin selection, multi-wallet manager, crash-safe wallet files, BIP-21 URIs, BIP-78 payjoin |
| Daemon | `Daemon.hs` | Config file parsing, daemonize, PID file, log file and SIGHUP, `/health`, systemd notify |
| Performance | `Performance.hs` | CPU feature detection (SHA-NI, AVX2 via `cbits/hwdetect.c`), parallel script checks |

`cbits/` holds the small C helpers the library links: hardware detection, a secp256k1
compatibility layer, double formatting, and declarations for the libzmq functions used.

## Tests

`test/Spec.hs` is the main hspec suite and imports the `*Spec.hs` files beside it. The other
suites in `haskoin.cabal` are separate executables: Core's script and sighash vectors
(`ScriptVectors.hs`, `SighashVectors.hs`, reading `resources/`), service-flag advertisement,
parallel script checking, I/O-fault handling (`Gate6*.hs`), and two restart tests
(`ReloadRewindTest.hs`, `ReconcileForwardTest.hs`). `test/regtest/core_parity.py` and
`test/p2a_followups_core_parity.py` compare a running haskoin with a running Bitcoin Core on
regtest; see [status.md](status.md).
